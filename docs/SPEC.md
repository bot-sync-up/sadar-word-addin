## 2. הצהרת מוצר

**קהל יעד עיקרי:** מעמדים ועורכים חרדיים העובדים בוורד על ספרי קודש, קונטרסים, עלונים וחוברות. אינטרנט מסונן (נטפרי/רימון), Office מקומי, Windows.

**קהל משני:** בתי דפוס קטנים, מכוני הוצאה לאור, מגיהים.

**מודל:** **חינמי לחלוטין — תרומה לקהילה.** אין תשלום, אין מנוי, אין גרסת פרימיום, אין איסוף נתונים. הבקשה עלתה מהקהילה בשרשור, והמוצר חוזר אליה. לכל משתמש נדרש מנוי Claude Code משלו — עלות שרובם כבר משלמים ממילא.

## 3. עקרון הליבה — חוזה הבטיחות

זו התובנה שהופכת את זה למוצר ולא ל-wrapper, וזו התשובה הישירה ללשכת הרב.

### 3.1 מה לא עושים

**התוסף לעולם אינו שולח את גוף המסמך למודל ואינו מקבל טקסט חזרה.**

בשיטה הידנית שבשרשור, המודל מקבל את הקובץ ומחזיר קובץ. גם אם בפועל הוא לא נוגע במלל — אין שום ערובה. ישיבישער צודק בהסבר שלו (מסמך ≠ טקסט חי), אבל צדק תיאורטי לא ישכנע עורך שאחראי על נוסח של ספר קודש.

### 3.2 מה כן עושים — ארבעה שלבים

### 3.3 מה זה קונה

- **ערובה מוכחת ולא הבטחה.** אפשר לומר בשיווק: "התוסף לא מסוגל טכנית לשנות את המלל, גם אם ירצה."
- **מסמכים בכל גודל.** שלד של ספר 600 עמ' הוא מטא-דאטה ותחיליות קצרות — לא הטקסט המלא. הבעיה שישיבישער תיאר נעלמת.
- **פחות חשיפה לסינון.** גוף הפסקאות הארוכות לא יוצא מהמחשב כלל — הרבה פחות סביר להפעיל את מסנן התוכן שחסם את אוריי.
- **מהירות.** אין המתנה ליצירת טקסט ארוך.

**נפח בפועל — נמדד, לא משוער.**
המדידה על ספר בדיקה של 840 פסקאות (92,016 תווי טקסט) נותנת שלד של 21,066 תווים — **22.9% מנפח המסמך**. שלוש החלטות עיצוב מביאות לשם:

| החלטה | מה היא חוסכת |
|---|---|
| פסקה ארוכה מ-180 תווים שאינה מודגשת נשלחת כאורך בלבד, בלי תחילית | היא גוף טקסט מובהק. התחילית לא מוסיפה מידע — והטקסט לא עוזב את המחשב |
| שדה שערכו כברירת המחדל של המסמך מושמט | ברוב הפסקאות הסגנון, הגופן והיישור זהים |
| פסקאות ריקות נשלחות כמערך אינדקסים ולא כאובייקטים | במסמך אמיתי הן כמחצית מהפסקאות |

*הערה: גרסה מוקדמת של מסמך זה נקבה ב-5%. המדידה הראתה 241% בטרם האופטימיזציות, ו-22.9% אחריהן. המספר כאן הוא הנמדד.*

### 4.3 גשר Claude Code — החיבור למנוי

**הבחירה:** התוסף אינו מחזיק מפתח API ואינו מפעיל שרת. הוא מריץ את ה-CLI של Claude Code שכבר מותקן ומחובר אצל המשתמש. זה בדיוק מה שטכנולוגי ג'וניור עושה היום ידנית — אנחנו רק מסירים את הידיים.

**זיהוי:**
1. `claude` ב-PATH
2. `%APPDATA%\npm\claude.cmd`
3. `%LOCALAPPDATA%\Programs\claude\claude.exe`
4. נתיב ידני שהמשתמש מגדיר

**קריאה:**
```
claude -p --output-format json --max-turns 1
```
הפרומפט נכתב לקובץ זמני ומוזרם ב-stdin. התשובה נקראת מ-stdout ומאומתת מול סכמה קשיחה.

**כללי ברזל בגשר:**
- אין הרשאות כלים לסוכן. הוא לא כותב קבצים, לא מריץ פקודות, לא ניגש לרשת. הוא מקבל טקסט ומחזיר JSON.
- Timeout של 120 שניות לחלון. חריגה → ביטול החלון והצעה לנסות שוב.
- JSON שלא עובר ולידציה → ניסיון אחד חוזר עם הודעת תיקון. נכשל שוב → החלון מסומן "לא סודר" והמסמך נשאר שלם.
- כל הריצות נכתבות ליומן מקומי שהמשתמש יכול לפתוח.

**אשף התקנה ראשונה:** אם Claude Code לא נמצא, התוסף מציג מסך בעברית עם השלבים (Node.js → התקנת ה-CLI → התחברות), כולל כפתור "בדוק שוב". בלי טרמינל וסיסמאות.

> ⚠️ **ממצא מהשטח — שני סוגי התקנה של Claude Code, ורק אחד מהם עובד.**
>
> אפליקציית **Claude Code Desktop** אורזת בתוכה בינארי `claude.exe` תחת
> `%APPDATA%\Claude\claude-code\<גרסה>\`. הבינארי הזה קיים ורץ, אבל הרצה עצמאית שלו מחזירה `Not logged in · Please run /login` — גם בסביבה נקייה לגמרי. האימות נשמר אצל האפליקציה ומועבר לתהליכי הבת שלה בלבד; הוא אינו זמין לתהליך חיצוני שמריץ את הבינארי.
>
> **ההתקנה העצמאית** (`npm install -g @anthropic-ai/claude-code` ואז `claude` → `/login`) שומרת אימות שכן זמין להרצה headless, וזה המסלול שהתוסף דורש.
>
> **המשמעות:** משתמש שיש לו רק את אפליקציית הדסקטופ — וזה בדיוק המצב שטכנולוגי ג'וניור תיאר בשרשור — לא יוכל להשתמש בתוסף עד שיתקין גם את ה-CLI. זו התקנה חד-פעמית של דקה, אבל היא חייבת להיות מוסברת היטב באשף, אחרת זו נקודת הנטישה הראשונה של המוצר.
>
> `ClaudeCodeEngine.CandidatePaths()` בודק את שני המסלולים ומעדיף את ההתקנה העצמאית. `sadar doctor` מדווח בדיוק מה נמצא ומה חסר.

> **הערה משפטית.** כיוון שהמוצר חינמי ואינו מסחרי, והוא מריץ את ה-CLI המותקן והמחובר של כל משתמש על המחשב שלו — המבנה זהה במהותו לאינטגרציית IDE או לכל עטיפה מקומית של Claude Code. אין ניתוב של צד שלישי דרך חשבון אחד, אין מכירה חוזרת של גישה, ואין הכנסה. הסיכון כאן נמוך. עדיין נכון לקרוא את תנאי השימוש לפני הפרסום — אבל זה לא חוסם פיתוח.

### 4.4 מבנה הנתונים

**שלד — מה שנשלח:**
```json
{
  "structure_hint": "הספר מחולק לסימנים. הטקסט מיד אחרי שם הסימן הוא כותרת ראשית.",
  "styles_available": ["כותרת 1", "כותרת 2", "כותרת 3", "רגיל", "ציטוט"],
  "paragraphs": [
    {"i": 140, "t": "", "empty": true},
    {"i": 141, "t": "סימן ג", "s": "רגיל", "b": true, "sz": 16, "al": "center", "len": 6},
    {"i": 142, "t": "דין הפסק בברכת המזון וגדריו", "s": "רגיל", "b": true, "sz": 14, "al": "center", "len": 27},
    {"i": 143, "t": "כתב הרמב\"ם בהלכות ברכות פרק ד' שהמפסיק בדיבור בין", "s": "רגיל", "b": false, "sz": 12, "al": "justify", "len": 412}
  ]
}
```

**החלטות — מה שחוזר:**
```json
{
  "decisions": [
    {"i": 141, "style": "כותרת 1"},
    {"i": 142, "style": "כותרת 2"},
    {"i": 143, "style": "רגיל"}
  ],
  "deletes": [140],
  "uncertain": [
    {"i": 189, "style": "כותרת 2", "why": "מודגש אך באמצע פסקה — ייתכן שזו הדגשה ולא כותרת"}
  ]
}
```

**ולידציה קשיחה לפני החלה:**
- כל `i` קיים במסמך ובחלון הנוכחי
- כל `style` נמצא ברשימת הסגנונות המותרים
- אין שדות נוספים מעבר לסכמה
- `deletes` מותר רק על פסקאות שסומנו `empty: true` בשלד

כל חריגה → ההחלטה נפסלת, לא מוחלת, ונרשמת ביומן.

### 4.5 מסמכים גדולים — חלונות וחפיפה

הבעיה שישיבישער תיאר ("מאות עמודים במכה אחת? לא בטוח שיחזיק") נפתרת מתחת למכסה המנוע:

- חלון של **400 פסקאות** עם **חפיפה של 30 פסקאות**.
- כל חלון מקבל גם **תקציר מבני מצטבר**: "עד כה זוהו 14 סימנים; שם סימן = פסקה מודגשת קצרה במרכז; כותרת משנה = פסקה מודגשת של 15–40 תווים".
- **מיזוג דטרמיניסטי:** בחפיפה, אם שני חלונות נתנו החלטות שונות לאותה פסקה — הפסקה עוברת אוטומטית ל"טעונות בדיקה". לא בוחרים שרירותית.
- סרגל התקדמות מציג "חלון 3 מתוך 12" ולא מסתיר את מה שקורה.

**המשתמש לא מפצל שום דבר ידנית.**

### 5.1 גרסה 1 — היקף מחייב

**א. החלת סגנונות לפי מבנה** — הליבה

**ב. סגנונות חסרים**

**ג. ניקוי דטרמיניסטי** — בלי AI כלל
- רווחים כפולים ומרובים בתוך שורה
- פסקאות ריקות עודפות (לפי כלל שהמשתמש קובע: כמה שורות ריקות בין סימן לסימן)

- טאבים שנועדו לעימוד ידני
- שורות ריקות בסוף המסמך

זה רץ מקומית, מהיר, וניתן להריץ אותו לבד בלי שום קריאה לקלוד.

**ד. קובץ כללים לשימוש חוזר**
הפיצ'ר שטכנולוגי ג'וניור בנה לעצמו ידנית. קובץ `כללים.json` לכל הוצאה/סדרה, שמכיל את ההגדרה המבנית, מיפוי הסגנונות, כללי הניקוי והחרגות. נשמר, נטען, משותף בין קבצים.

**ה. למידה מספר מעומד קיים**

**ו. תצוגה מקדימה לפני החלה**
טבלה בחלונית: פסקה | תחילת הטקסט | סגנון נוכחי ← סגנון מוצע | ✓

## 6. יישור טורים — הערת מו"פ

ישיבישער כתב שזו "העזרה הגדולה והמטורפת ביותר" ושמגיע לזה מדריך נפרד. זה גם הפיצ'ר שיהפוך את המוצר מנוח לחיוני. אבל צריך לומר בכנות: זו בעיה שונה לגמרי מהליבה.

**למה:** החלת סגנונות היא החלטה *סמנטית* על פסקה — בדיוק מה ש-AI טוב בו. יישור טורים הוא בעיה *גיאומטרית* ברמת השורה: מרווח בין תווים, קשידה, מניעת "נהרות" לבנות, שליטה בשורה יתומה. המודל לא רואה את הפריסה בפועל.

**הכיוון הסביר:** לולאת מדידה מקומית — התוסף קורא את מיקומי השורות בפועל מוורד, מזהה שורות בעייתיות, ומריץ אלגוריתם מקומי שמכוונן `Font.Spacing` / קשידה בטווחים מוגדרים. ה-AI נכנס רק להחלטה איפה *מותר* למתוח ואיפה אסור (למשל: לא בתוך שם קדוש, לא בציטוט).

**המלצה:** לא ב-V1. לפתוח לזה מסמך מו"פ נפרד אחרי שהליבה בשטח. אבל **כן להזכיר במפת הדרכים הפומבית** — זה מה שיגרום לאנשים בשרשור לחכות למוצר.

## 7. אילוצי סינון — נטפרי

אוריי דיווח על חסימת json בעבודה על ספרי קודש. טכנולוגי ג'וניור נמנע מלהעביר טקסט חי בצ'אט מאותה סיבה. זה אילוץ תשתית אמיתי שחייב מענה מתוכנן.

**מה מקטין את החשיפה כבר בעיצוב:**
- נשלחים רק 60 תווים ראשונים לפסקה, לא גוף הטקסט
- אין תשובות טקסט חוזרות — רק אינדקסים ושמות סגנון
- ניקוי דטרמיניסטי רץ לגמרי מקומית

**מצב מסונן — מתג בהגדרות:**
במקום טקסט, נשלחת **טביעת אצבע מבנית** בלבד:
```json
{"i":141, "pattern":"HEB_WORD + HEB_LETTER", "words":2, "b":true, "sz":16, "al":"center", "len":6}
```
המודל מסיק את המבנה מהתבניות ומהעיצוב בלבד, בלי לראות מילה אחת. פחות מדויק — אבל עובד, ועובד גם על החומר הרגיש ביותר.

**זיהוי חסימה:** כשקריאה נכשלת, `NetFreeDetector` מבחין בין חסימת סינון (תעודת TLS חלופית, דף חסימה) לבין תקלת רשת אמיתית, ומציג הודעה מדויקת בעברית עם הצעת פעולה — במקום "שגיאה לא ידועה" שתשרוף את אמון המשתמש.

## 8. הפצה והתקנה

**דרישות מערכת:**
- Windows 10/11
- Word 2016 ומעלה (32 או 64 סיביות)
- .NET Framework 4.8
- VSTO Runtime — נכלל במתקין
- Node.js + Claude Code CLI מותקן ומחובר

**מתקין:** קובץ EXE יחיד בעברית. בודק את הדרישות, מתקין מה שחסר, ומסיים באשף החיבור לקלוד.

**ערוצי הפצה:**
- דף הורדה פשוט תחת `syncup.co.il` (או תת-דומיין ייעודי) — חייב להיות פתוח בנטפרי
- קישור ישיר בשרשור המקורי בפורום ובשרשור ייעודי חדש
- ריפו GitHub ציבורי — קוד פתוח, `issues` כערוץ דיווח באגים

**חתימת קוד — הוכרע: ללא.**
הפרויקט יוצא בלי תעודת חתימה. שתי החלטות ארכיטקטוניות מצמצמות את הנזק:

1. **תוסף COM ולא VSTO.** הרישום נעשה דרך `regasm` תחת המשתמש הנוכחי (HKCU) בלבד. אין ClickOnce, אין מסך "Publisher: Unknown Verified" של VSTO, ואין דרישת הרשאות מנהל. זה מוריד את רוב האזהרות שחתימה נועדה למנוע.
2. **מה שנשאר** הוא סימון "קובץ מהאינטרנט" של Windows על ה-ZIP שהורידו. הפתרון: מדריך בן שורה — לחיצה ימנית על הקובץ > מאפיינים > **בטל חסימה**, לפני החילוץ. מתועד בהוראות ההתקנה, וסקריפט ההתקנה מזהה את המצב ומסביר אותו בעברית.

זו עדיין חוויה פחות טובה מהתקנה חתומה, אבל היא עוברת — והיא חינם.

**תמיכה:** כיוון שזה מוצר חינמי בהתנדבות — התמיכה היא דרך שרשור בפורום ו-GitHub Issues בלבד. חשוב לכתוב את זה במפורש בדף ההורדה כדי לא ליצור ציפייה לתמיכה אישית.

**עדכונים:** בדיקת גרסה בהפעלה, עדכון בלחיצה.

## נספח: יומן פריסה — מה שנשבר בדרך

התוסף נבנה ונבדק במלואו. הפריסה לוורד חשפה חמישה כשלים שאף אחד מהם לא מופיע בשום מדריך, וכולם נכשלים **בשקט מוחלט**. מתועדים כאן כי הם יחזרו אצל כל משתמש.

| # | הכשל | איך התגלה | תיקון |
|---|---|---|---|
| 1 | `regasm` דורש הרשאות מנהל — כותב ל-HKLM | ההתקנה נכשלה מיד | רישום COM ידני תחת HKCU. אפס הרשאות |
| 2 | וורד 32 סיביות מול PowerShell 64 — הפניית WOW64 שולחת כל אחד למפתח אחר | הרישום "הצליח" ווורד לא ראה כלום | רישום בשתי תצוגות הרישום |

## נספח: סיבוב QA

סיבוב ביקורת מלא על הקוד ועל הבדיקות. שלושה באגים אמיתיים נמצאו בקריאה, ושלושה נוספים התגלו בזכות בדיקות חדשות.

### באגים שנמצאו בביקורת קוד

**1. כל כפתורי הרצועה היו מתים** — חמור
`Connect` הוגדר עם `ClassInterfaceType.None`. וורד קורא לפונקציות הרצועה (`onAction="OnAnalyze"`) דרך `IDispatch::GetIDsOfNames` על אובייקט התוסף; עם `None` ה-IDispatch הראשי הוא `IDTExtensibility2`, שאין בו את השמות האלה. התוצאה: התוסף נטען, הלשונית מוצגת יפה — **וכל שישה הכפתורים לא עושים כלום.** הוחזר ל-`AutoDispatch`.

**2. גישה ל-COM מחוט משני**
`MainForm` קרא את המסמך בתוך חוט הרקע. אובייקטים של וורד שייכים לחוט שיצר אותם; מגע בהם מחוט אחר נכשל באקראי או נתקע. תוקן: הקריאה מהמסמך נעשית על חוט וורד, ורק אחריה העבודה האיטית עוברת לרקע. נוסף `Orchestrator.Analyze(snapshot, useEngine)` שאינו נוגע במסמך כלל.

**3. מאות קריאות COM מיותרות בזמן מילוי הטבלה**
כל שורה שנוספה לטבלה שינתה את הבחירה והפעילה קפיצה לפסקה במסמך. תוקן בדגל `_populating`.

**קטנים:** החלון לא נסגר באמת בעת כיבוי וורד (נוסף `ForceClose`) · כתיבה ל-stdin של תהליך שנפל הסתירה את השגיאה האמיתית · חיפוש ריבועי ברשימת המחיקות · עמימות `CS0467` ב-Word interop נסגרה בהמרה מפורשת.

### פער כיסוי שנסגר

`DocxBuilder` ייצר רק פסקאות עם הרצה אחת, ולכן **האלגוריתם המסוכן ביותר בקוד מעולם לא נבדק**: חלוקת הטקסט המנוקה חזרה בין ההרצות הקיימות תוך שמירה על הדגשות בתוך הפסקה. כתיבה נאיבית של הפסקה כמחרוזת אחת הורסת אותן.

נוספה תמיכה בפסקאות רב-הרצה ושלוש בדיקות: הדגשה פנימית ששורדת ניקוי, רווח כפול שנמחק בדיוק על גבול בין הרצות, וטאבים ורווחים קשיחים. כולן עוברות — האלגוריתם תקין, אבל עד עכשיו לא היה לכך שום כיסוי.

### שתי בדיקות שעברו לשווא

- **בדיקה שקראה את הקובץ המקורי.** בדיקות ה-XML בחנו את הקובץ שעל הדיסק בלי שהמסמך נשמר אחרי ההחלה, ולכן אימתו את המצב שלפני. תוקן בשמירה מפורשת.
- **עוזר בדיקה שחיפש מחרוזת.** הבדיקה חיפשה `<w:b/>`, בעוד ש-`XDocument` מסדרת אלמנט ריק כ-`<w:b />`. שלוש בדיקות דיווחו על היעדר הדגשה שקיימת בפועל. הוחלף בפרסור XML.

המוצר אינו קשור לספק אחד. `IDecisionEngine` הוא ממשק צר — נכנס שלד, יוצא JSON — וכל הצינור שמעליו אינו יודע מי עונה.

מסלול המנוי עדיף: מי שכבר משלם על מנוי אינו משלם שוב לפי שימוש. זו גם הסיבה שהוא מוצג ראשון בממשק.

### שלוש החלטות שנבעו מהאילוצים

**HTTP גולמי ולא SDK.** הפרויקט נבנה עם `csc.exe` בלבד, בלי NuGet, כדי שכל אחד בקהילה יוכל לבנות אותו על מחשב רגיל. שלוש בקשות POST אינן מצדיקות לוותר על זה.

**הפרומפט עובר ב-stdin ולעולם לא כארגומנט.** שלד של ספר מגיע לעשרות אלפי תווים, ושורת פקודה בווינדוס חסומה סביב 32K. ארגומנט ארוך מדי נכשל באמצע ובלי הסבר.

**מפתחות מוצפנים ב-DPAPI.** הקובץ שנשמר אינו קריא למשתמש אחר במחשב ואינו שמיש במחשב אחר. זו לא כספת, אבל זה מונע מפתח בטקסט גלוי בתיקיית ההגדרות. הבדיקות מאמתות שהמפתח אינו מופיע בקובץ.

### שני באגים שנתפסו בבדיקה מול השירותים האמיתיים

**TLS 1.3 תלה את ג'מיני.** ביקשתי `Tls12 | Tls13`, ו-.NET Framework 4.8 אינו תומך ב-1.3 במלואו. מול Anthropic, OpenAI ו-OpenRouter זה עבד — הם הסתפקו ב-1.2. מול נקודת הקצה של גוגל לחיצת היד נתקעה עד ל-timeout, שנראה בדיוק כמו שרת שאינו זמין. `curl` ענה מאותה כתובת ב-0.18 שניות, וזה מה שהפריד בין "השירות חסום" לבין "הקוד שלי שבור". התיקון: TLS 1.2 בלבד.

**גוגל מחזירה 400 ולא 401 על מפתח שגוי.** בלי טיפול מיוחד המשתמש קיבל JSON גולמי במקום משפט שאפשר לפעול לפיו. כעת גוף התשובה נבדק, וכל ארבעת הספקים נותנים את אותה הודעה בעברית.

שני אלה התגלו רק בגלל שהבדיקה נעשתה מול נקודות הקצה האמיתיות עם מפתח שגוי בכוונה — בדיקה שאינה עולה כלום ואינה דורשת חשבון.
